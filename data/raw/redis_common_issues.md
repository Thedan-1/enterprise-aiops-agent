# Redis 常见故障模式

## 缓存穿透（Cache Penetration）

请求查询一个数据库和缓存里都不存在的 key，每次都会绕过缓存直接打到数据库。如果被恶意/大量请求不存在的 key，数据库压力会骤增。

应对：对不存在的结果也缓存一个空值（设置较短TTL）；使用布隆过滤器提前拦截明显不存在的key。

## 缓存击穿（Cache Breakdown）

一个热点 key 在缓存中过期的瞬间，大量并发请求同时穿透到数据库，瞬间压垮数据库。

应对：热点key设置永不过期+后台异步刷新；或者用互斥锁（mutex），只让一个请求去数据库重建缓存，其他请求等待。

## 缓存雪崩（Cache Avalanche）

大量 key 在同一时间集中过期，或者 Redis 实例本身宕机，导致所有请求同时穿透到数据库。

应对：给不同key的TTL增加随机抖动，避免同时过期；Redis做高可用（哨兵/集群），避免单点。

## 连接数耗尽

Redis 客户端连接池配置不合理，或者出现连接泄漏，导致新请求无法获取连接，应用侧报 `connection pool exhausted` 或类似错误——这个症状和数据库连接池耗尽的表现非常相似，需要先看清楚是应用连的哪个组件耗尽了连接池，不能想当然认为一定是数据库的问题。

## 内存不足 / Key 驱逐

Redis 内存达到 maxmemory 上限后，根据配置的驱逐策略（如 allkeys-lru）淘汰旧 key。如果应用没有为这种情况做容错（假设缓存一定命中），可能引发缓存命中率骤降进而打满数据库。
