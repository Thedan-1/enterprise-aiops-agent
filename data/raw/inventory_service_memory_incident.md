# 历史故障案例：inventory-service 内存压力导致响应变慢

## 故障现象

inventory-service 在一次促销活动期间出现 P95 延迟从 100ms 上升到 950ms，同时监控显示 Memory 使用率持续在 85% 以上，日志中出现较多 GC 暂停时间超过 800ms 的记录。

## 根因分析

排查发现是一个缓存本地Map没有设置容量上限，促销期间SKU查询请求量激增，本地缓存无限增长导致堆内存压力增大，JVM频繁触发Full GC，GC期间应用线程暂停（Stop-The-World），表现为响应延迟飙升。

## 修复

将本地无界缓存替换为有容量上限+LRU淘汰策略的缓存实现，并补充了内存使用率的告警阈值。

## 经验教训

内存类问题的典型特征：CPU不一定很高，但Memory持续走高、GC频率和暂停时间上升，最终表现为延迟增加而不是直接报错。这类问题在早期只会表现为P95/P99延迟的缓慢爬升，容易被忽略，等到接近OOM时才会集中爆发。建议对Memory使用率和GC暂停时间单独设置早期预警阈值，不要只依赖QPS/ErrorRate这类"事后才升高"的指标。
