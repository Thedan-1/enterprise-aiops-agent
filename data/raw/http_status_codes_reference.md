# HTTP 状态码速查（运维视角）

## 4xx（客户端问题，通常不是服务端故障）

- 400 Bad Request：请求参数不合法
- 401 Unauthorized：未认证
- 403 Forbidden：无权限
- 404 Not Found：资源不存在
- 429 Too Many Requests：触发限流

## 5xx（服务端问题，需要运维介入）

- 500 Internal Server Error：应用内部未捕获异常，需要看应用自身日志和堆栈
- 502 Bad Gateway：网关（Nginx/LB）从上游收到无效响应或连接被重置，通常是上游服务的问题，详见《Nginx 502/504 网关错误排查指南》
- 503 Service Unavailable：服务暂时不可用，常见于服务过载后主动限流拒绝请求，或者服务正在启动/发布中还未就绪
- 504 Gateway Timeout：网关等待上游响应超时，通常伴随上游变慢

## ECONNRESET / Connection Reset

不是标准HTTP状态码，而是TCP层面的连接被对端重置。常见于：对端进程崩溃、对端主动关闭了一个还在使用中的连接（比如连接池里的连接超过了服务端的keepalive超时）、网络设备（如LB）主动断开了空闲连接。

## 判断优先级建议

看到5xx错误码本身只是"症状"，不是"根因"。排查时应该优先确认：这是网关层（502/504）还是应用层（500/503）？是持续性的还是间歇性的？是否伴随流量突增或最近的发布？
