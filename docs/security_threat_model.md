# V2 安全威胁模型

## 资产

- 租户知识文档、日志、指标和历史工单。
- 用户身份、角色、审计记录和模型 API Key。
- Agent 工具权限和检索证据。

## 信任边界

1. 浏览器输入是不可信的。
2. LLM 输出是不可信的建议，不能作为授权结果。
3. 检索文档可能包含间接提示词注入。
4. 工具适配层是最终权限执行点。

## V2 已缓解风险

- 直接 Prompt Injection：独立输入 Guard、攻击用例测试。
- Excessive Agency：只读工具、角色工具白名单、最大迭代和工具预算。
- 跨租户数据泄露：每个租户使用独立 Retrieval Runtime；审计查询强制 tenant scope。
- 暴力请求与费用放大：用户级滑动窗口限流、输入长度限制。
- Token 篡改：HMAC 签名和过期时间校验。
- 无法追责：登录、阻断、限流和聊天结果写入 append-only JSONL 审计。

## V2 仍未解决

- 演示 Token 不是标准 OIDC；生产应接企业身份提供商并支持密钥轮换、撤销和 MFA。
- JSONL 审计不是不可篡改存储；生产应进入受保护的集中日志平台。
- 间接 Prompt Injection 目前依赖只读/最小权限降低影响，没有对所有文档做内容净化。
- 没有真实企业数据分级、脱敏与保留策略。
- PostgreSQL Row Level Security 尚未在本机 Docker 环境验证。

## 依据

V2 采用的原则是最小功能、最小权限、在用户上下文执行、关键动作独立授权，以及不把系统提示词当作安全边界。这些与 OWASP Agent/LLM 安全建议一致。
