# V2 Roadmap：从面试原型到可公开交付的工程样板

## 目标

V2 不冒充生产 AIOps 平台。它要做到：功能可直接演示、数据规模足以支持方向性实验、关键安全边界可测试、请求可审计，并能清楚说明距离生产环境还差什么。

## 验收标准

1. 知识库不少于 25 篇原创企业文档，覆盖网关、数据库、缓存、消息队列、容器、发布、容量和安全。
2. 评测集不少于 100 条，并通过重复 ID、未知文档引用、类别分布和数据泄漏检查。
3. 演示环境支持登录、角色权限、租户隔离、请求限流和审计查询。
4. 所有工具由确定性策略授权，LLM 不能自行扩大权限；V2 工具继续保持只读。
5. 对 Prompt Injection、跨租户访问、越权审计、超长输入和暴力请求有回归测试。
6. 输出端到端延迟分解；至少完成一项有前后数据的优化。
7. 完整测试通过，公开仓库不包含 API Key、真实个人数据或构建缓存。

## 阶段

- V2.1 数据可信度：扩文档、扩评测、数据质量门禁。
- V2.2 安全边界：认证、RBAC、tenant scope、prompt guard、rate limit、audit。
- V2.3 性能与可观测性：检索缓存、阶段延迟、P50/P95/P99 基线。
- V2.4 产品展示：登录页、租户/角色信息、审计视图、演示场景。
- V2.5 公开交付：README、威胁模型、限制清单、GitHub PR。

## 明确不做

- 不接入真实公司的 Prometheus、ELK 或 Jira 账号。
- 不提供任何写入、删除、重启服务等高风险工具。
- 不引入 Kafka、Kubernetes、Milvus、多 Agent 或长期记忆。
- 不声称 100 条自建评测集具有生产统计显著性。
